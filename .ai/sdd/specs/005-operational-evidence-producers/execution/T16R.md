### Background and intuition

- **planned / deterministic-rule** — The approved boundary requires the model
  to produce only a Step 9.9 draft; the pinned converter and renderer own
  canonical and rendered outputs. Source:
  `design.md` Section 20 and `tasks.md` T16R.
- **observed / supporting-evidence** — Previously, the runner let the model
  write report-shaped output and then mutated that object with operational
  metadata. Source:
  `scripts/run-spec005-praxen-behavior-verifier.ps1` inspected before this
  implementation.
- **implemented / supporting-evidence** — Each attempt now has isolated
  `staging`, `converter`, `canonical`, `rendered`, and `operational`
  directories plus `result.json`; existing attempt directories are refused.
  Source: `scripts/run-spec005-praxen-behavior-verifier.ps1`.

### Execution order and invariant

```text
fresh Haiku session
  -> one staging Step 9.9 Markdown draft
  -> pinned manifest_to_findings.py
  -> immutable canonical JSON + SHA-256
  -> pinned render.py + pinned template
  -> immutable HTML/TXT
  -> runner-created operational projection
  -> adapter verifies projection against canonical sibling
```

- **implemented / deterministic-rule** — JSON in staging, missing/duplicate or
  stale drafts, malformed converter output, wrong target/version/timestamp,
  renderer failure, binding mismatch, privacy keys, unsafe role paths, and
  canonical hash mismatch all fail closed.
- **implemented / deterministic-rule** — A retry requires both a new
  `AttemptId` and explicit `-RetryApproved`; no attempt directory is reused.
- **implemented / deterministic-rule** — A producer failure creates a bounded
  `partial` result, names the producer/target/reason, pauses for operator
  direction, remains non-release-eligible, and never invokes bundle promotion.
  An exception is also non-clean and non-release-eligible.
- **implemented / supporting-evidence** — Legacy canonical Praxen reports
  remain readable, but legacy `operational` metadata is ignored without the
  runner-created binding.

### Edge cases, trade-offs, and observable consequences

- **verified / supporting-evidence** — A controlled fixture passed through the
  real pinned converter and renderer; repeating conversion produced identical
  SHA-256 output.
- **verified / supporting-evidence** — Missing draft, model-authored JSON,
  malformed manifest, stale draft, wrong target, renderer failure, binding
  tampering, wrong version/run/target/hash, and privacy-key fixtures were
  rejected.
- **inferred / recommendation** — The adapter must be pointed at the
  runner-owned `operational` directory so it can resolve the exact canonical
  sibling through the bounded role name. This preserves the canonical file
  unchanged at the cost of a paired-artifact ingestion contract.
- **verified / supporting-evidence** — The labelled partial fixture caused the
  existing release builder to exit non-zero before bundle output. No T16R or
  partial-builder artifact remained under repository evidence paths.
