## As Built

### Background and core intuition

- `[planned]` A-005 Section 22.3 and TD-014 make one create-once descriptor the
  only release start and runtime-target authority.
- `[implemented]` The descriptor contract contains exactly five fields:
  `schemaVersion`, `releaseRunId`, `startedAt`, `runtimeTargetId`, and
  `purpose`. Source:
  `contracts/release-run-descriptor-v1.schema.json` and
  `src/lib/release-run-descriptor.ts`.
- `[implemented]` The Windows PowerShell 5.1 creator writes only
  `%LOCALAPPDATA%\SancusSight\operations\runs\<releaseRunId>\release-run.json`
  with `FileMode.CreateNew`, UTF-8 without BOM, canonical millisecond UTC, the
  fixed target `sancussight-local-runtimes`, and purpose `a002-t16`. Source:
  `scripts/new-spec005-t16-release-descriptor.ps1`.

### Execution order and invariants

1. `[implemented]` The creator validates the bounded run ID, canonical start,
   fixed target/purpose, fixture-root contract, and run-root/run-ID agreement
   before opening the descriptor with exclusive create semantics.
2. `[implemented]` The parser rejects BOM, malformed JSON, missing, unknown,
   or duplicate fields, wrong types/version/purpose/target, unsafe IDs,
   noncanonical timestamps, and any noncanonical descriptor path.
3. `[implemented]` A process binder snapshots content hash plus file identity
   and refuses another path, rewrite, or reused-process rebind. OTLP and Pi
   revalidate that binding before every qualifying emission.
4. `[implemented]` The failure matrix reads run ID, start, target, and output
   root from the descriptor. Conflicting legacy environment identity fails;
   `observedAt`, filesystem time, import time, and stale environment values
   cannot replace descriptor facts.
5. `[implemented]` OTLP binds and exposes safe descriptor identity before
   creating/listening on the loopback server. Pi binds and exposes identity
   before the first fake/real `pi.on` registration. Wrong identity, malformed
   descriptor, rewrite, or rebind emits no qualifying output.

### Edge cases and trade-offs

- `[verified]` Pre-run, future, exact 30-minute deadline,
  one-millisecond-over, and evaluation-over-deadline cases are explicit.
- `[verified]` A changed filesystem modification time does not change
  `startedAt`; the file content remains authority.
- `[verified]` The legacy
  `operations/manifests/release-run.example.json` cannot substitute for the
  canonical descriptor.
- `[verified]` Stale/conflicting
  `SANCUSSIGHT_RELEASE_RUN_ID` and `SANCUSSIGHT_RUNTIME_TARGET_ID` fail closed
  before listen/registration/output.
- `[implemented]` Runtime processes re-read the small descriptor before each
  output. This adds bounded local file I/O in exchange for detecting a
  post-start rewrite rather than continuing to qualify against changed
  release state.
- `[implemented]` The matrix rotation fixture now uses a deliberately
  different-length replacement ID (`rotation-newer`). This removes a
  same-size/same-timestamp filesystem race without changing the exercised
  rotation contract.
- `[planned]` T16R5-T16R7 remain responsible for Praxen, selection/builder,
  Pipelock/UI, and end-to-end descriptor migration. T16R4 does not claim sole
  end-to-end authority yet.
