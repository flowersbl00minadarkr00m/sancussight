## Implementation

### Fixed pre-token launcher

`invoke-spec005-t16-pretoken.ps1` now:

- resolves only the approved `claude`, `codex`, and `pi` providers through
  canonical `Get-Command -All` records;
- accepts exactly one Claude/Codex `Application` `.exe` or Pi
  `ExternalScript` `.ps1` leaf and rejects missing, ambiguous, or unsupported
  command shapes;
- uses fixed provider-specific argument vectors and the canonical project
  working directory and runtime target;
- exposes `-PlanOnly` with zero child invocation and an isolated
  `-FixtureMode` used only by fake-provider tests;
- PowerShell-hosts Claude/Codex executables through `-Command` and Pi scripts
  through `-File`, closes stdin immediately, reads both streams
  concurrently with byte bounds, and terminates the exact child tree on
  timeout;
- rejects overflow, non-zero exit, invalid UTF-8, a leading UTF-8 BOM,
  authentication/authorization text, and any result other than the
  case-sensitive exact provider marker after CR/LF normalization and outer
  ASCII whitespace trimming; and
- returns bounded facts only. It does not return prompt, response, stream body,
  credential, secret, unrestricted path, or command-line content.

### Non-provider local readiness

`verify-spec005-t16-local-readiness.ps1` now checks:

- the fixed 20-file entrypoint/prerequisite set;
- all six required inventory source identities and inventory contract facts;
- both approved Worker Remit hashes;
- canonical collector data-directory selection, including legacy-alias
  agreement and the requirement that collector data remain outside the
  project;
- fixed loopback source configuration and expected listener state for
  collector `43117`, OTLP bridge `43120`, and AIMap `11434`; and
- privacy-safe readiness facts without starting, probing through, or invoking
  a provider.

Fixture mode supplies isolated roots, remits, and loopback listener metadata
for tests without weakening production defaults.

### Regression coverage

The focused suites use fake provider shims only and cover exact vectors,
`.exe`/`.ps1` host modes, paths with spaces, target/cwd propagation, stdin
closure, omitted-root resolution from a non-project working directory,
plan-only zero invocation, ambiguous/unsupported/missing resolution, strict
marker positives and negatives, CR/LF normalization, BOM, auth before marker,
non-zero exit, stdout/stderr bounds, timeout/tree termination, missing
entrypoints, remit mismatch, collector-root conflict, loopback-port conflict,
missing listeners, and zero provider invocation from readiness checks.

`test-spec005-t16-pretoken.ps1 -ParseOnly` provides the required Windows
PowerShell 5.1 parse sweep for every `scripts/*.ps1` and
`operations/**/*.ps1` file.

## As Built

### Background and core intuition

- `[implemented]` The former pre-token seam depended on improvised shell
  resolution, quoting, transport, and marker behavior. The checked-in launcher
  turns that seam into one deterministic executable trust boundary.
  Source: `scripts/invoke-spec005-t16-pretoken.ps1`.
- `[implemented]` Provider output is private transient input, not evidence.
  Only bounded qualification facts cross the launcher boundary.
  Source: `scripts/invoke-spec005-t16-pretoken.ps1`.
- `[implemented]` Local readiness is deliberately separate from provider
  access. It inspects fixed non-secret files, hashes, roots, and loopback
  listener metadata only.
  Source: `scripts/verify-spec005-t16-local-readiness.ps1`.

### Execution order

1. `[implemented]` Resolve exactly one accepted provider command record.
2. `[implemented]` Return the fixed plan without invocation, or launch the
   accepted fake/real command shape with canonical target and working
   directory facts.
3. `[implemented]` Close stdin, concurrently bound both streams, and apply the
   timeout/tree-kill boundary.
4. `[implemented]` Check exit, overflow, UTF-8/BOM, authentication text, then
   the exact normalized marker.
5. `[implemented]` Return sanitized facts or fail closed before any later token
   step.
6. `[implemented]` Run local readiness independently; it never calls the
   launcher or a provider.

### Invariants and edge cases

- `[verified]` Plan-only performs zero provider invocation and exposes the
  exact fixed vectors.
- `[verified]` When `-ProjectRoot` is omitted, both entrypoints derive the
  canonical project root from `$PSCommandPath` after parameter binding,
  independently of the caller's working directory.
- `[verified]` Authentication/authorization text fails even when an exact
  marker is also present.
- `[verified]` A leading BOM, changed case, punctuation, prose, a fence,
  non-ASCII outer whitespace, non-zero exit, stream overflow, and timeout all
  fail closed.
- `[verified]` Duplicate command records, unsupported command types, and
  missing commands fail before launch.
- `[verified]` Timeout cleanup terminates the fake provider process tree within
  the suite's bounded deadline.
- `[verified]` Readiness detects missing files, remit drift, collector-root
  disagreement, port conflict, and missing listener state without invoking a
  provider.

### Tradeoffs and future use

- `[implemented]` The launcher retains fixed approved vectors instead of
  accepting caller-supplied arbitrary arguments. Changes require a reviewed
  source edit.
- `[implemented]` Production readiness uses fixed ports and fixed source
  configuration; fixture overrides exist only to make isolated regression
  tests deterministic.
- `[planned]` T16R4-T16R7 and the eventual explicitly authorized one-shot
  release flow may consume these controls. This worker did not implement,
