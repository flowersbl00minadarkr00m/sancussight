### As Built

- Background: the Passport previously rendered six always-expanded
  `<section>` wrappers, making secondary material consume the first viewport.
- Core intuition: native disclosure state is sufficient; React keys define
  only when defaults reset. No controlled accordion or persisted preference
  is needed.
- Prior behavior: all six section bodies were visible after selection.
- New behavior: Summary starts open and remains user-operable; Portability,
  Dependencies, Evidence, Decisions, and History start closed for each newly
  selected asset.
- Execution order: selection chooses an asset; keyed disclosure instances
  mount with defaults; native browser interaction owns open state; unrelated
  rerenders reuse the same keyed nodes; a different asset ID remounts them.
- Invariants: one Passport DOM, six identities, unchanged content/callback
  ownership, unchanged T1 strip, unchanged row/detail and narrow Back focus,
  no new persistence, state machine, dependency, route, network, or schema.
- Edge cases: user-closing Summary is preserved during current-asset
  rerenders; save feedback does not remount disclosures; selecting another
  asset restores approved defaults.
- Trade-off: disclosure state intentionally resets when asset identity
  changes and is not remembered across browser sessions.
- Observable consequence: the selected Passport is compact by default while
  retaining native keyboard and assistive disclosure semantics.
