## As Built

The Assets view now has one persistent state owner for query, facet choices,
narrow presentation, row refs, and return-focus intent. The selected asset
continues to be owned by `App` through the unchanged `selectedId`/`onSelect`
contract. This preserves the approved architecture and allows later
Attention/Home/Exit Drill links to enter the same Passport without a second
detail implementation.

The desktop DOM contains exactly two sibling cards: the catalog region and
the canonical Passport region. CSS selects the approved two-column layout at
900 CSS pixels and above. Below 900 pixels, the same two regions remain in one
DOM but exactly one is displayed according to the narrow view state, so there
is no duplicate catalog or duplicate focus order.

On narrow selection, the activating asset ID and button ref are retained,
selection remains in the parent contract, and the stable Passport heading is
focused after render. Back returns to the existing catalog DOM without
resetting query, filters, selection, or scroll state. It restores focus to the
still-rendered selected/originating row; when criteria exclude that row, it
focuses Clear criteria, and when no such recovery control exists it focuses
the catalog heading. A polite live message explains either fallback.

Passport facts are organized into the approved six-section outline. Recorded
facts use the registry fields as supplied. Portability and evidence freshness
reuse the T1 deterministic facet values. Signals show their recorded category
as recorded fact, deterministic finding, missing evidence, or human decision.
Absent values use `Not recorded`, `None recorded`, `Never recorded`, or
`Missing / unavailable` according to the field type. Existing mutation
callbacks remain the only review, verification, and drill commands.

No approved requirement or design divergence was observed. The installed
skill catalog does not expose `sdd-understanding`, and this worker may not edit
the shared `understanding.md`; this structured As Built section is the durable
orchestrated-worker fallback required by `sdd-exec`.
