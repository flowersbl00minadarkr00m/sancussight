## Privacy Negatives

- Hostile prompt/tool-argument values containing email and absolute-path data
  reject the envelope and appear nowhere in the preview.
- Omitted-private rows never own a `value`.
- Raw session/source-record IDs, artifact names, summaries, and non-allowlisted
  attributes do not enter alignment output.
- Feature 010 packet workflow/asset identifiers and names do not enter the
  Statement.
- Unknown profiles/predicate types, packet tampering, unsafe packet values,
  invalid digests, unavailable Web Crypto, invalid Statement shapes, and
  download failures return failure-only results without a verification or
  download claim.

## As Built Understanding

### Core intuition and execution order

`truth_label: verified`; sources: implementation plus the ordered checks above.
The alignment seam starts after the collector privacy boundary: it accepts only
already normalized `runtime-telemetry` envelopes, rechecks the exact attribute
allowlist, and emits a fixed comparison matrix. It never reconstructs a span or
parses OTLP. The Statement seam starts after Feature 010 truth: packet shape and
packet digest are verified first, then the packet's validated digest and
bounded counts are copied into one exact unsigned predicate. Canonical bytes
and their confirmation digest are computed only after exact Statement
validation; download rechecks all three.

### Invariants and edge cases

- Profile IDs are fixed and unknown IDs fail before a preview or Statement is
  produced.
- Alignment values are bounded metadata tokens, numbers, booleans, or safe
  SHA-256 references; private content families remain valueless.
- Unknown safe event families are `unsupported`, not guessed.
- Empty accepted runtime evidence produces explicit `missing` rows.
- Statement top-level, subject, digest, predicate type, and predicate keys are
  exact; extensions, digest mismatch, or changed truth booleans fail.
- Statement export time does not affect Statement bytes or digest.
- Download failure may leave a validated Statement in memory but creates no
  successful export claim.

### Trade-offs and observable consequences

The implementation deliberately supports a narrow pinned metadata profile.
Standards-compatible fields outside that map remain unsupported, and valid
content-bearing OpenInference attributes remain prohibited. The exported file
is structurally recognizable and digest-bound, but supplies no signer,
authentication, certification, external verification, or transparency claim.
T3 owns presentation and storage; T2 intentionally adds neither.

Standalone `sdd-understanding` generation was skipped because that skill is not
present in this session's installed skill catalog. The required high-burden As
